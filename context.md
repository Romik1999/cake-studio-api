## 2. Архитектура и Стек
**Проект:** B2B SaaS "Cake Studio" (конструктор тортов + админка).
**Стек Backend:** Python 3.12, FastAPI, Pydantic v2, SQLAlchemy 2.0 (async), PostgreSQL, Alembic, Docker, Ruff.
**Стек Frontend:** React 19, TS, Vite, MUI, Zustand, TanStack Query v5, FSD (в разработке).

## 3. Мультитенантность (Реализовано)
- Одна база данных. Изоляция данных по `tenant_id` (Shared Schema).
- **Модель Tenant:** таблица `tenants` (slug, name, domain). Есть 3 системных тенанта в сиде: `platform` (для суперадмина), `moments`, `bakery2`.
- **Роли:** Enum `UserRole`: `CUSTOMER`, `ADMIN`, `SUPERADMIN`. Поле `is_admin` удалено. Суперадмин привязан к тенанту `platform`.
- **Железобетонная защита на уровне БД:** Все таблицы имеют `tenant_id`. Настроены *composite foreign keys* (например, `(tenant_id, user_id) -> users(tenant_id, id)`). БД физически не даст сослаться на чужой тенант.
- **Резолвинг тенанта:** В `app/api/deps.py -> get_current_tenant`. В `local` берет из заголовка `X-Tenant`, в проде — из `Host` (домена).
- **Защита от кросс-тенантности:** `get_current_user` ищет юзера по `user_id` И `tenant_id` из текущего тенанта. Токен, выданный на `moments`, не сработает на `bakery2`.

## 4. Статус Backend (ГОТОВО)
- Модели, Alembic-миграции (с composite FK и каскадами), Pydantic-схемы.
- Сервисы (`user`, `ingredient`, `preset`, `cake_config`, `order`, `statistics`, `telegram`) полностью переписаны под `tenant_id`.
- В `_calculate_price` и создании связей добавлена проверка, что все `ingredient_id` принадлежат текущему тенанту (кидает `ValueError`).
- Все роуты обновлены: `GET` — публичные в рамках тенанта, `POST/PATCH/DELETE` — только для `get_tenant_admin`.
- Разделение прав: `get_tenant_admin` (управляет меню), `get_superadmin` (управляет тенантами в `/superadmin/tenants`).
- Telegram-уведомления привязаны к `tenant_id`, а не к конкретному админу.
